# PostService — макети інтерфейсу ПР-44

Редагований CASE-проєкт: **PostService-UI.drawio**. Інструмент: diagrams.net / draw.io Desktop 32.6.10.
Усі PNG експортовані самим draw.io з масштабом 150%; в них також вбудовано редагований дизайн.

## Як відкрити

Відкрийте `PostService-UI.drawio` у diagrams.net Desktop або в редакторі https://app.diagrams.net/ через відкриття локального файлу.
Сторінка **«Навігація та стани макетів»** містить посилання на всі екрани. У редакторі перехід відкривається через посилання в підказці до кнопки; у режимі перегляду достатньо натиснути кнопку.
PNG можна переглядати звичайним переглядачем зображень; це основні файли для здачі практичної.

## Склад

- `desktop/` — 9 екранів Windows Forms, базовий розмір 1280 × 900.
- `web/` — 9 екранів широкого вебінтерфейсу, 1440 × 960.
- `mobile/` — 9 адаптованих вебекранів шириною 390, з вертикальним прокручуванням довгих форм.
- `navigation.png` — карта навігації; разом 28 PNG.
- `manifest.json` — перелік сторінок і відповідних зображень.
- `navigation.json` — 201 перехід між сторінками дизайну.

У кожному варіанті: home — головна; list — список; new — нове відправлення; errors — помилки форми; edit — редагування; details — деталі; about — про програму; delete — підтвердження видалення; deleted — успішне видалення.

## Прийняті рішення

Однакові назви дій: «Нове відправлення», «Редагувати», «Деталі», «Видалити», «Зберегти», «Скасувати». У списку виділяється одне відправлення. Після видалення з'являється повідомлення про успіх, вибір скидається; дії над невибраним записом недоступні.

На широкому екрані використовується таблиця, на мобільному — картки. У вебваріанті бічна навігація перебудовується у компактні вкладки. Поля форми на мобільному розташовані в один стовпець, дії мають висоту щонайменше 44 одиниці макета.

Валідація виконується після «Зберегти». Показуються зведення помилок, рамка, іконка «!» і конкретний спосіб виправлення. На широкому екрані пояснення розташовані праворуч, на вузькому — під полем. У прикладі помилок коректні значення інших полів збережені.

Вага та розміри мають бути додатними, оголошена цінність — невід'ємною або порожньою. Ім'я й адреса відправника та одержувача, вміст і спосіб доставки обов'язкові. Це вимоги дизайну клієнтської валідації для наступної реалізації.

Поля відповідають PostingGetDto: Id і CreatedAt відображаються в деталях лише для читання; ширина, висота та глибина подані окремими полями форми. Вартість нового відправлення визначається під час збереження, оскільки PostingPostDto не приймає Price; у редагуванні Price доступне, як у PostingPutDto. Description також включено.

Макети демонструють стани й навігацію, а не викликають API. Дані прикладів умовні. Перед видаленням показується окремий діалог із номером відправлення, коротким описом і кнопками «Скасувати» / «Видалити». Екран деталей не має полів редагування.

Перевірено 28 PNG, усі посилання та досяжність 27 екранів від головних сторінок відповідних варіантів. HTML/CSS-сторінка не використовується як результат цієї роботи.
