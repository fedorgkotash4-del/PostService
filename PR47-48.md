# Практична робота 47–48

Windows Forms «Облік поштових відправлень» продовжує наявне рішення PostService.
Макети списку, створення, редагування, перевірки полів і видалення з `Design/PR44`
адаптовано до двох форм: `PostingList` та спільної `PostingEditor`.

## Запуск із вихідного коду

Потрібні Windows та .NET SDK 10 із підтримкою Windows Forms.
Відкрийте `PostServiceSolution/PostService.slnx` у Visual Studio й виберіть
профіль «PostService — сервер і клієнт». У VS Code відкрийте
`PostService.code-workspace` і запустіть однойменний профіль.

Або в окремих терміналах із каталогу `PostServiceSolution`:

```powershell
dotnet run --project PostService --urls http://localhost:5036
dotnet run --project PostService.App
```

Спочатку дочекайтеся запуску API, потім запускайте клієнт. Клієнт також коротко
очікує сервер під час спільного запуску. Іншу адресу можна передати через
змінну середовища `POSTSERVICE_API_URL` із кінцевим `/`.

## Реалізовано

- Головний список, створення, редагування подвійним натисканням або кнопкою,
  видалення з підтвердженням, ручне та автоматичне оновлення після збереження.
- Спільний модальний діалог: створення через POST, завантаження через GET за Id,
  редагування через PUT із відповідним Id. Скасування не надсилає змін.
- Обов’язкові відправник, одержувач, вміст; додатні вага та габарити;
  необов’язкові цінність і опис. Цінність та ціна не можуть бути від’ємними.
- Кома й крапка в числах, помилки біля полів, збереження введених даних при
  відмові API та повідомлення про недоступність сервера.
- При створенні ціну визначає сервер; при редагуванні її можна змінити.
  Id і дату створення користувач не вводить.

Готові локальні збірки зберігаються в `Deliverables/PR47-48` і не включаються до Git.
